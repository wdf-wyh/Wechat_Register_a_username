## 一、整体架构

```
┌──────────────────────────────────────────────────┐
│                  调度服务器 (PC)                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────────────┐  │
│  │ 行为剧本  │ │ 任务队列  │ │  监控面板         │  │
│  │ 引擎     │ │ 调度器    │ │  (Prometheus +    │  │
│  │          │ │          │ │   Grafana)        │  │
│  └──────────┘ └──────────┘ └──────────────────┘  │
│                      │                            │
│              Python 主控程序                       │
│         (uiautomator2 + adb 通信)                 │
└──────────────────────┬───────────────────────────┘
                       │ USB Hub / ADB over TCP
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
┌────────────┐  ┌────────────┐  ┌────────────┐
│ Moto手机 1  │  │ Moto手机 2  │  │ Moto手机 N  │
│ 微信实例 1  │  │ 微信实例 2  │  │ 微信实例 N  │
│ 4G SIM卡 1  │  │ 4G SIM卡 2  │  │ 4G SIM卡 N  │
│ uiautomator2│  │ uiautomator2│  │ uiautomator2│
│ agent       │  │ agent       │  │ agent       │
└────────────┘  └────────────┘  └────────────┘
```

**核心原则**：

- 每台手机 = 1 个微信号 = 1 张独立 4G SIM 卡，物理隔离
- uiautomator2 通过 ADB 与手机通信，调用 Android 原生 UiAutomation API
- 元素定位采用**混合策略**：优先使用控件树（text/resourceId/className），因微信 FLAG_SECURE 屏蔽 UiAutomation API 时自动降级为坐标 fallback + 截图像素分析 + OpenCV 模板匹配 + EasyOCR 文字识别
- PC 端 Python 主控程序负责剧本调度、行为生成、状态监控

## 二、技术栈

| 层次 | 技术 | 用途 | 说明 |
|------|------|------|------|
| **设备** | Moto 测试真机 | 微信运行载体 | 自带真实传感器、真实设备指纹，每台 1 号 |
| **通信** | ADB | PC 与手机通信桥梁 | USB 连接（优先）或 ADB over TCP |
| **控制** | uiautomator2 | 手机端 UI 自动化 | 基于 Android UiAutomation，优先控件树定位；被 FLAG_SECURE 屏蔽时自动降级为坐标/截图/OCR 混合定位 |
| **脚本** | Python 3.10+ | 主控逻辑编写 | 生态丰富，uiautomator2 原生 Python 绑定 |
| **AI 内容** | DeepSeek API / 本地 LLM | 聊天内容与文案生成 | 生成差异化自然语言内容 |
| **调度** | Python asyncio / APScheduler | 任务调度与定时 | 轻量，无需额外中间件 |
| **数据** | SQLite / JSON | 账号状态持久化 | 每号独立行为档案 |
| **监控** | Prometheus + Grafana | 运行状态监控 | 可选，后期接入 |

### uiautomator2 核心能力对应

| 需求 | uiautomator2 实现方式 |
|------|----------------------|
| **元素定位** | `d(text="朋友圈")`, `d(resourceId="com.tencent.mm:id/xxx")`, `d(className="android.widget.EditText")` |
| **点击** | `d(text="发送").click()` |
| **长按** | `d(text="消息").long_click(duration=0.5)` |
| **滑动** | `d.swipe(sx, sy, ex, ey, duration=0.3)` 或 `d(scrollable=True).scroll.forward()` |
| **输入文字** | `d.send_keys("你好")` 或 `d(focused=True).set_text("内容")` |
| **截图** | `d.screenshot("screen.png")`（用于截图像素分析定位、OCR识别、异常记录，非纯调试用途） |
| **应用管理** | `d.app_start("com.tencent.mm")`, `d.app_stop("com.tencent.mm")` |
| **设备信息** | `d.info` 获取设备型号、分辨率、Android 版本等 |
| **等待元素** | `d(text="微信", wait_timeout=10.0)` 等待元素出现 |
| **坐标点击** | `d.click(x, y)` 百分比坐标 fallback（FLAG_SECURE 场景下使用） |
| **IME 注入** | `d.set_input_ime(True)` + `d.send_keys()` ADBKeyboard IME 静默文字注入 |

> **注意**：由于微信对部分界面启用了 FLAG_SECURE，控件树定位可能失败。系统会自动降级为坐标 fallback（`config/wechat_elements.py` 中的 `COORDINATE_FALLBACK`），或交由 `core/screen_locator.py`（截图像素分析）和 `core/moment_poster.py`（OpenCV+OCR）处理。

## 三、环境搭建

### 3.1 手机端配置

```
1. 开启开发者模式（设置 → 关于手机 → 连续点击版本号）
2. 开启 USB 调试（设置 → 开发者选项 → USB 调试）
3. 开启"不锁定屏幕"（开发者选项 → 不锁定屏幕）
4. 安装 uiautomator2 agent：
   python -m uiautomator2 init
   （此命令通过 ADB 将 agent APK 推送到手机并安装）
5. 安装微信最新版（通过应用商店或官网 APK）
6. 插入独立 4G SIM 卡，关闭 WiFi
```

### 3.2 PC 端环境

```bash

source wechat_env/bin/activate  # Windows: wechat_env\Scripts\activate

pip install opencv-python       # 仅用于异常截图分析，不用于元素定位
pip install pillow               # 截图处理
pip install loguru               # 日志
pip install apscheduler          # 任务调度
pip install openai               # LLM API 调用

# 可选
```

## 五、行为剧本引擎

行为剧本定义了每个账号每天需要执行的操作序列。剧本引擎负责按照当前账号所处阶段（信任积累期/轻度互动期/正常使用期/成熟期）选择合适的剧本模板，并在预设的时间窗口内执行。

### 5.1 剧本数据结构

```python
"""
行为剧本 = 一系列"动作项"，每个动作项包含：
- 动作类型
- 时间窗口（在一天中的大概时间）
- 持续时间/次数
- 参数（如文案内容、联系人等）
- 随机偏移范围
"""

from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

class ActionType(Enum):
    OPEN_WECHAT = "open_wechat"
    SCROLL_MOMENTS = "scroll_moments"
    LIKE_MOMENT = "like_moment"
    COMMENT_MOMENT = "comment_moment"
    POST_MOMENT = "post_moment"
    SCROLL_CHANNELS = "scroll_channels"
    LIKE_CHANNEL = "like_channel"
    READ_ARTICLE = "read_article"
    FAVORITE_ARTICLE = "favorite_article"
    SEARCH = "search"
    SEND_MESSAGE = "send_message"
    SEND_IMAGE = "send_image"
    SEND_VOICE = "send_voice"
    SEND_EMOJI = "send_emoji"
    MAKE_PAYMENT = "make_payment"
    DOWNLOAD_EMOJI = "download_emoji"
    MODIFY_GROUP_NICKNAME = "modify_group_nickname"
    IDLE = "idle"  # 在线但不操作
    SLEEP = "sleep"  # 不活跃

@dataclass
class Action:
    action_type: ActionType
    time_window_start: str    # "08:00"
    time_window_end: str      # "09:00"
    duration_seconds: tuple   # (min, max) 持续时间范围
    params: dict = field(default_factory=dict)
    random_offset_minutes: int = 30  # 时间窗口随机偏移量（分钟）

@dataclass
class DailyScript:
    """单日行为剧本"""
    stage: str                # 所属阶段
    is_weekend: bool          # 是否周末版
    actions: list[Action]     # 动作列表
```

### 5.2 各阶段剧本定义

#### 5.2.1 信任积累期（第1-2周）

此阶段仅进行内容消费，不做互动操作，让账号建立正常使用模式：
- 08:00 - 开启微信，查看消息
- 08:30 - 刷朋友圈但不互动
- 12:00 - 刷视频号
- 12:30 - 阅读公众号文章并收藏
- 14:00 - 浏览小程序（随机选择小程序打开）
- 17:00 - 浏览微信支付页面，小额支付 1 次
- 19:00 - 刷朋友圈 + 点赞 1-2 条
- 21:00 - 刷视频号 + 点赞
- 22:00 - 睡前刷朋友圈
- 23:00-07:00 - 不活跃（睡眠期）

#### 5.2.2 轻度互动期（第3-4周）

在信任积累期基础上增加：
- 与 2-3 个好友聊天（文字 + 表情 + 图片）
- 发朋友圈 2-3 条/周
- 语音消息 1 次/周
- 下载表情包 1-2 套/周
- 主动加 1-2 个好友/天

#### 5.2.3 正常使用期（第2-3个月）和成熟期（3个月+）

逐步增加互动频率和社交深度，放宽限量阈值。剧本结构与上述类似，参数调高，时间窗口更灵活。

## 六、拟人化操作引擎

拟人化引擎是整个系统对抗微信行为检测的核心模块。"行为序列与时序分析"是微信最核心的 AI 检测层，因此操作行为必须在以下维度做到高度逼近真人。

### 6.1 拟人化维度对照表

| 检测维度 | 机器人特征 | 拟人化策略 | 实现位置 |
|---------|-----------|-----------|---------|
| 点击间隔 | 固定间隔/均匀随机 | 对数正态分布 | `Humanizer.random_sleep()` |
| 点击坐标 | 精准命中中心点 | 正态分布偏移 (μ=中心, σ=3-5px) | `Humanizer.human_offset()` |
| 滑动轨迹 | 直线/恒定速度 | Bézier曲线 + 缓入缓出 | `Humanizer.bezier_swipe_path()` |
| 操作节奏 | 固定模式 | 加入犹豫(3%) + 误操作(1%) | `Humanizer.should_hesitate()` |
| 输入方式 | 瞬时完成 | 逐字输入 + 随机停顿 + 偶尔删改 | `WeChatControl._type_text()` |
| 时序规律 | 每天同一时间同一操作 | 时间窗口 ±30-60min 随机偏移 | `ScriptExecutor._schedule_actions()` |
| 行为多样性 | 仅几种固定操作 | 多套剧本 + 随机动作选择 | 行为剧本引擎 |
| 传感器 | 全0/固定值 | 真机天然解决 | 无需额外处理 |

## 七、多设备管理

### 7.1 设备管理架构

```
scheduler/batch_manager.py
├── 设备注册：每台手机与微信账号一对一绑定
├── USB Hub 管理：支持多台手机通过 USB Hub 连接到一台 PC
├── 连接池：维持所有设备的 uiautomator2 连接
└── 设备状态监控：在线/离线/异常
```

### 7.2 批量操作策略

批次管理器：按注册时间将账号分组，不同批次处于不同养号阶段。

流水线模式：
- Week 1: 批次A (10个号) → 信任积累期
- Week 3: 批次B (10个号) → 信任积累期，批次A → 轻度互动期
- Week 5: 批次C (10个号) → 信任积累期，批次B → 轻度互动期，批次A → 正常使用期
- Month 3: 批次A 成熟出仓 → 可用于 benchmark

### 7.3 设备并发执行

多设备并发执行：使用 asyncio 为每台设备创建独立的协程。

所有设备在同一时间段内的行为模式应略有不同：
- 不同设备的行为时间窗口略有偏移
- 不同设备使用不同的随机种子
- 不同设备的内容（文案/聊天）差异化

## 八、内容与话术管理

### 8.1 内容体系

```
content/
├── post_templates.py     # 朋友圈文案模板（100+条）
├── chat_templates.py     # 聊天话术模板（多场景）
├── comment_templates.py  # 评论模板
├── search_keywords.py    # 搜索关键词库
└── llm_client.py         # LLM API 调用封装
```

### 8.2 文案模板设计原则

1. **生活化**：60% 日常碎碎念、美食、风景、心情
2. **互动性**：30% 可引发评论/回复的内容
3. **信息性**：10% 行业资讯、转发文章

4. **差异化**：每个账号的文案方向不同（人格化），避免同质化
5. **随机化**：即使同类内容，也要从多个模板中随机选取，并可通过 LLM 改写

### 8.3 内容生成与账号人格化

LLM 内容生成客户端调用 DeepSeek API 或本地 LLM 生成差异化内容。安全措施包括：每次调用使用不同的 prompt 和 temperature，在 prompt 中注入账号"人设"信息确保内容风格稳定但不雷同，记录生成历史定期检查是否存在同质化趋势。

每个微信号有一个"人格档案"，用于指导内容生成和行为风格。不同账号的人设应差异化，避免同质化。

## 九、风险监控与预警

### 9.1 健康检查项

账号健康检查：定期检测微信账号的功能是否正常。

检查项：
- 朋友圈是否可见（"仅自己可见"= 被降权）
- 加好友是否需要验证（异常信号）
- 消息发送是否延迟
- 是否频繁出现滑块验证
- 部分功能是否被限制（群聊/朋友圈/支付等）

### 9.2 预警处理流程

```
预警信号                 →  冷却策略              →  恢复条件
──────────────────────────────────────────────────────────
朋友圈降权              →  停止发圈 ≥7天         →  连续3天正常
加好友需验证            →  停止加人 ≥7天         →  连续3天正常
消息延迟 >5s            →  减少操作 48-72h       →  延迟恢复 <1s
滑块验证频繁(>3次/天)   →  停止操作 24h          →  24h内0次
功能限制                →  转入纯消费模式         →  手动处理
```

### 9.3 预警状态机

预警状态机定义了账号在不同风险等级之间的转换规则，根据健康检查结果自动切换行为策略（正常/冷却/暂停）。

## 十、数据持久化与账号档案

### 10.1 数据库设计

```sql
-- 账号表
CREATE TABLE accounts (
    id TEXT PRIMARY KEY,              -- 账号唯一标识
    wechat_id TEXT UNIQUE,            -- 微信号
    phone TEXT,                       -- 绑定手机号
    device_serial TEXT,               -- 绑定的手机设备序列号
    imei TEXT,                        -- 设备 IMEI
    sim_number TEXT,                  -- SIM 卡号
    registration_date TEXT,           -- 注册日期
    batch_name TEXT,                  -- 所属批次
    stage TEXT,                       -- 当前阶段
    persona_id TEXT,                  -- 人格模板 ID
    level TEXT DEFAULT 'L1',         -- 账号等级 L1-L5
    state TEXT DEFAULT 'normal',     -- 当前状态
    mode TEXT DEFAULT 'full',        -- 行为模式：full/consume_only/paused
    notes TEXT,                       -- 备注
    created_at TEXT DEFAULT (datetime('now')),
    updated_at TEXT DEFAULT (datetime('now'))
);

-- 行为日志表
CREATE TABLE action_logs (
```

## 十二、红线与注意事项

### 12.1 绝对禁止

| 红线行为 | 原因 |
|---------|------|
| 使用模拟器/云手机 | 微信3分钟内通过132维设备指纹识别，秒封 |
| 使用微信多开/外挂/Xposed | 微信客户端主动检测，直接触发封号 |
| 同一IP批量操作多个微信号 | 触发 Ianus 图分析，关联封杀 |
| 养的号互相加好友/进同一群 | Ianus 社区检测 → Sybil 集群 → 一锅端 |
| 批量同时加好友 | 单日超过阈值即功能限制 |
| 使用 Hook/内存注入方式 | 逆向微信DLL，随时可能被检测且随版本失效 |
| 频率换设备登录 | 触发异地登录安全预警 |

### 12.2 关键操作限量

| 操作 | 新号 (< 1月) | 老号 (> 3月) |
|------|-------------|-------------|
| 主动加好友 | 1-2人/天 | 10-20人/天 |
| 发朋友圈 | 2-3条/周 | 1-3条/天 |
| 群发消息 | 禁止 | ≤ 4次/月 |
| 支付 | 1-2次/天 | 正常使用 |
| 语音/视频通话 | 1次/周 | 正常使用 |

### 12.3 微信版本适配注意事项

1. **微信更新频繁**：微信客户端每隔几周就会更新，resource-id 可能发生变化。优先使用 `text` 和 `description` 定位。
2. **元素定位字典维护**：每次微信版本更新后，使用 `python -m uiautomator2 weditor` 重新抓取控件树，更新 `wechat_elements.py`。
3. **灰度发布兼容**：微信对不同用户可能推送不同版本，注意处理元素定位的 fallback 逻辑。

### 12.4 安全操作规范

1. **USB 连接优先**：ADB over TCP 虽然方便，但 USB 连接更稳定，避免网络波动导致自动化中断。
2. **手机不锁屏**：开发者选项中开启"不锁定屏幕"，避免自动化中途因锁屏卡死。
3. **定期检查 ADB 授权**：手机重启后可能需要重新授权 USB 调试，建立自动化前置检查。
4. **异常恢复**：每个操作包裹在 try-catch 中，失败后记录日志 + 截图，不影响其他设备运行。
5. **分时段操作**：所有账号的操作严格控制在 07:00-23:00 之间，夜间不执行任何自动化动作。

### 13.7 发朋友圈详细方案 (`core/moment_poster.py`)

采用 **OCR + OpenCV + ADBKeyboard IME** 混合方案，6 阶段全自动流程：

| 阶段 | 目标 | 技术 | 说明 |
|------|------|------|------|
| 1 | 找相机图标 | OpenCV 模板匹配 | 多尺度(0.7x~1.2x)匹配，右上角区域搜索 |

| 6 | 找"发表"按钮 | EasyOCR 区域扫描 | 只扫右上角区域，点击后验证返回朋友圈 |

### 13.13 健康检查方案 (`monitor/health_check.py`)

两层检查体系：

**设备层 (DeviceHealthChecker)** — 12项基础设施检查：

| # | 检查项 | 说明 |
|---|--------|------|
| 1-3 | ADB连接 / ATX Agent / 设备信息 | 底层连通性 |
| 4-6 | 微信安装 / 冷启动 / 前台状态 | 微信可用性 |
| 7-12 | Tab切换 / 截图 / 朋友圈 / 搜索 / 视频号 / 存储 | 核心功能 |

**账号层 (AccountHealthChecker)** — 6项风险检测：

| # | 检查项 | 说明 | 风险权重 |
|---|--------|------|---------|
| 1 | 微信启动+首页 | 冷启动到首页 | 0 |
| 2 | 朋友圈可见性 | OCR检测降权关键词 | 0.5 |
| 3 | 搜索功能 | 复用 SearchHelper | 0.1 |
| 4 | 发消息 | 复用 MessageSender | 0.3 |
| 5 | 滑块/验证码 | OCR检测弹窗 | 0.3 |
| 6 | 功能限制 | OCR检测限制词 | 0.5 |

风险评分: <0.2=NORMAL, 0.2-0.4=WARNING, 0.4-0.6=COOLDOWN, >=0.6=SUSPENDED

**调用示例**：

```python
from monitor.health_check import DeviceHealthChecker, AccountHealthChecker

# 设备层
DeviceHealthChecker().run_all()  # → JSON报告

# 账号层  
AccountHealthChecker(d, contact="gas").run_all()  # → 风险评分+状态
```
