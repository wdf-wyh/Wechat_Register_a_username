# 单例运行 — 真机验证命令

> 在项目根目录执行。先确认设备在线：`wechat_env\Scripts\python.exe main.py status`

---

## 一、14 天冷启动剧本（推荐）

走 **模板 → BaseScript handler → WeChatControl**，与 `main.py debug/run` 生产路径一致。

建议先关闭 AI 编排，确保测的是固定模板：

```bash
set USE_AI_GOD_PLANNER=0
```

### 抽查单天（约 10–20 分钟/天）

```bash
wechat_env\Scripts\python.exe main.py cold-start-burst --day 1
wechat_env\Scripts\python.exe main.py cold-start-burst --day 4
wechat_env\Scripts\python.exe main.py cold-start-burst --day 8
```

Day1 含「读文+留言」：缩时模式仍保留 **约 10 分钟（duration=600）** 与 `comment_rate=1.0`，全程可读可评，不会「成功 1 条就停评」。

Day1 / 4 / 8 分别覆盖四个相位（社交种子、内容生态、深度互动、场景渗透）。

### 14 天连续缩时（约 1–2 小时）

```bash
wechat_env\Scripts\python.exe main.py cold-start-burst
```

### 14 天完整时长（按模板原始 duration，可能数小时）

```bash
wechat_env\Scripts\python.exe main.py cold-start-burst --full
```

### 指定设备

```bash
wechat_env\Scripts\python.exe main.py cold-start-burst --serial <设备序列号>
```

**前置条件**（否则部分动作会跳过）：人设需配置 `seed_friends`（加好友）、`chat_friends`（深聊，如 `30金色`）、`seed_groups`、`public_accounts`。

---

## 二、单功能冒烟（底层能力）

直接调用 `WeChatControl` / `core` 模块，**不经过剧本 handler**。用于快速验证「这一步在真机上能不能做成」。

公众号文章阅读+评论

```bash
wechat_env\Scripts\python.exe scripts/public_account_comment_smoke.py
```

一对一聊天（Vision 多页截图优先；有语音会先转文字再截图）

```bash
wechat_env\Scripts\python.exe -m scripts.deep_chat_smoke "30金色"
```

语音转文字

```bash
wechat_env\Scripts\python.exe -m scripts.voice_transcribe_smoke "30金色"
```

发朋友圈（智能选图+配文）

```bash
wechat_env\Scripts\python.exe -m scripts.post_moment_smoke
```

刷视频评论

```bash
wechat_env\Scripts\python.exe scripts/smoke_channels_ai_comment.py
```

朋友圈每日互动20次（优先秒评大V）

```bash
wechat_env\Scripts\python.exe scripts/smoke_moments_daily_interact.py
```

玩官方小游戏（发现→游戏→找游戏→立即玩）

```bash
wechat_env\Scripts\python.exe -m scripts.play_mini_game_smoke
```

## 三、离线检查（不需要手机）

模板生成 + 编排逻辑自检（约 30 秒）：

```bash
wechat_env\Scripts\python.exe main.py enterprise-smoke
```

---

## 四、推荐验证顺序

1. `enterprise-smoke` — 离线模板无误
2. `cold-start-burst --day 1/4/8` — 各相位 handler 链真机抽查
3. `cold-start-burst` — 14 天连续缩时全量验证
4. 单功能 smoke — 某一步失败时单独定位底层问题

## 五、每日定时（生产）

`main.py run` 每次启动会按账号 `registration_date` 算出今天是 Day N，只跑当天剧本。用系统定时每天调一次即可，不要用 `cold-start-burst`。

先确认库里注册日正确，再**以管理员身份**安装任务（会弹 UAC）：

```powershell
powershell -ExecutionPolicy Bypass -File scheduler\install_daily_task.ps1
```

或双击 `scheduler\install_daily_task.bat`：先点 UAC「是」，**窗口会停住**。看到 `registered: WechatFarm_DailyRun` 和 `SUCCESS` 再按任意键关闭。普通窗口会「拒绝访问」，这是 Windows 限制。

立刻试跑：双击 `scheduler\daily_run.bat`（不要双击 `.ps1`，会报「无法注册包」）。或：

```powershell
powershell -ExecutionPolicy Bypass -File scheduler\daily_run.ps1
```

默认：每天 07:00 `run`，23:00 `report`，周一 08:00 `advance`。日志在 `logs/cron.log`。电脑需保持登录，手机 USB 在线。

每个动作结束后会写中文 `[证据]` 行到 `logs/cron.log`（成功/失败都有），格式如：`做了什么：点赞朋友圈 | 结果：成功 | 图片是：<绝对路径>`；在 Cursor 里对路径 **Ctrl+点击** 即可打开 JPG。图片也在 `screenshots\<账号ID>\`，库表 `action_logs.screenshot_path` 同步存路径。`sleep` / `idle` 不截图。
